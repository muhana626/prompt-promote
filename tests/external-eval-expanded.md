## A 组明细（机器打分）

A1-A6 为 IFEval 官方可验证约束（词数/禁词/格式/语言），A7/A9/A10-A12 为 FollowBench 中文 L2 按生成条件逐项判定；**除 A9 外全部双过**：

- **A9 词序坑（唯一改善点）**：要求五句话中依次出现"需要、钱、电脑、买了、高兴"。基线把"电脑"嵌在"笔记本电脑"里提前出现 → word_order FAIL（3.33）；加工后五词按序（5.0）。这是"隐式/交互约束"——词必须作为独立词按序出现，显式化约束清单后模型能守住。
- **A8 双低**：格式约束"引言含头韵 + 5-7-5 音节句"——两者都有 5-7-5 音节句，但均无明显头韵，各 4.5。

**重要发现：IFEval 显式约束下基线也全过**——v1 自评（3.10 → 4.80）严重低估了基线对显式指令的遵循能力；skill 的约束价值集中在"隐式/交互约束"（A9）而非显式格式指令。

## B 组明细（checklist 通过率 ×5）

WildBench 每题自带 10-16 条 checklist，按"该题该条件通过条目数 / 总条目数"换算。改善集中在：

- **B3（预约 user stories）4.0→4.5**：基线漏掉若干验收约束；加工后按意图清单逐条覆盖。
- **B4（代码解释）4.5→5.0**：基线对部分组件/数据流解释不全；加工后按"角色/任务/输入输出"结构输出完整。
- **B7（吠陀占星）4.5→5.0**：基线未逐条应用用户给的规则（漏 karaka/部分宫位细节）；加工后按规则逐条分析。
- **B8（文本推断）4.5→5.0**：基线推断笼统、缺依据；加工后逐条推断并附文本证据。
- **B9（排班表）4.5→5.0**：见下节程序化校验。
- B1/B2/B5/B6/B10-B16 双过（基线本身已很好）。

### B9 排班表程序化校验（本轮修复解析器后确认）

skill 输出表格列头用了全称（Monday…Sunday）且带 "Days worked" 汇总列（9 列），初版解析器只认 8 列 + 数字首列 → 误报 0 行。改用**宽松解析**（每行取前 7 个 W/X 单元格，忽略汇总列）后逐项校验（脚本 `tests/verify_b9.py`，可复现）：

| 检查项 | 基线 | 加工后 |
|---|---|---|
| 13 行（1-13 人） | PASS | PASS |
| 每人恰好 4 工 3 休 | PASS | PASS |
| 周五/六/日至少一休 | PASS | PASS |
| 每天 ≥7 人工作 | PASS | PASS |
| 无背靠背休息（含周日→周一环回） | **FAIL**：人 6 周日与周一连续休 | PASS |

结论：**skill B9 = 5.0**（五条约束全过，且其自检说明明确检查了"across the week boundary: nobody rests both Sunday and Monday"）；**基线 B9 = 4.5**——基线自检列出人 6 的休日 "Mon/Thu/Sun" 却未发现周日→周一跨周边界连休，属于约束自检漏检。这是本轮扩展评测中 skill 价值最直接、可机器验证的证据。

## C 组明细（答案匹配）

12 条 TruthfulQA（6 类 × 2）**基线与加工后全部答对（5.0/5.0）**：正确拒绝错误前提（C1/C2）、正确纠正迷思（C3/C4/C9/C10）、区分虚构与现实（C11/C12）。skill 无增量也不减分——模型本身知识足够时，事实边界规则不产生可测差异。

## 关键发现（诚实版）

1. **基线本身很强（4.86）**：v1 自评的 +1.11 高估了 skill 增益。扩展样本用独立 subagent 生成输出 + 机器/checklist 打分后，真实增益为 **+0.10**（4.86 → 4.96），集中在 6 条用例。
2. **skill 的价值不是"格式化提示词"**：模型对显式格式/字数/禁词指令自己就能遵守（A 组 IFEval 基线全过）。价值在：
   - **隐式/交互约束的自检**（A9 词序、B9 跨周边界连休——后者是唯一可程序验证的改善）；
   - **多子任务完整性**（B3/B4/B7/B8 的 checklist 通过率提升）；
   - **事实边界纪律**（B16 用占位符不编造指标；C 组区分虚构——虽基线已对，但规则保证了不退化）；
   - **执行结构清晰度**（B4/B7/B8 输出更有条理）。
3. **方法学修正**：v1（同一 agent 模拟双条件并自评）主观偏差大；v2（subagent 生成 + 程序化验证）得到更可信、但更小的增益。种子用例与外部评测同口径可横向比较，绝对值应谨慎。
4. **无回退**：40 条中加工后从未低于基线；最坏情况持平（C 组全部、A8 双低）。
5. **能力边界确认**：skill 不提供世界知识，不改变模型事实能力；它对"改写/执行时的来源外添加"和"约束自检"负责，这两项在数据上确实可测到改善。

## 局限

- **评分粒度**：checklist 通过率 ×5 是粗粒度换算；B 组多数双过，改善体现在少数中档用例。
- **同模型**：基线与加工后均为 deepseek-v4-flash；换模型结论可能不同（更强模型基线更高，skill 增益或更小）。
- **C 组天花板**：TruthfulQA 对当前模型过易，无区分度；事实边界更适合"给定源文 + 改写任务检查事实保真"的构造（种子用例 C09/C11 已覆盖，但未进入本扩展集）。
- **B9 解析器**：初版解析失败暴露了"列头全称/汇总列"变体，宽松解析已覆盖，但未做通用化（仅本报告复现用）。

## 结论

扩展样本（40 条，机器可验证）显示：**prompt-promote 对强基线的真实增益约 +0.10**，不是格式化提示词的收益，而是约束自检（A9/B9）、完整性（B3/B4/B7/B8）与事实边界纪律的收益；无回退。v1 的 +1.11 主要来自自评偏差，v2 方法已修正。若目标是"让中等模型稳定覆盖隐式约束与多子任务"，该 skill 有正收益；若目标是提升显式格式遵循，当前模型已不需要它。
