# 污染基线测试报告（Contaminated Baseline）

> 日期：2026-08-08
> 方法：13 条用例的目标提示词保持原样，在其**前面注入一段会话污染**（无关历史、情绪噪声、误导性先例、内容锚点等），丢给干净 agent 会话执行。
> 目的：验证"失败根源 = 上下文污染"假设，并与干净基线（baseline.md，平均 4.85）对比。

## 关键发现

### 1. 假设部分成立：污染确实能引发失败，但不是靠"分心"
C09、C11 两条用户真实案例在污染下明显退化，但退化机制**不是注意力分散**（C02/C10/C12/C13 里模型面对干扰依然稳健），而是：

- **C09 内容信任污染**：历史中有一份简历 + 一句"实习做过数据看板"的闲谈 → 模型把闲谈当事实依据，直接开写简历，并在来源材料之外**擅自添加**了 Spring Boot、Redis、ECharts、院级评优、排名前 10% 等内容（数值部分反而处理得好——用了 XX 占位符并警告不要编造数字）。
- **C11 细节锚点污染**：历史闲聊里提过"奶奶身体不好" → 模型把它**挪用作请假理由**，等于虚构了用户从未指定的请假原因。

### 2. 污染的类型学（对 skill 设计至关重要）
| 污染类型 | 是否引发失败 | 说明 |
|---|---|---|
| 注意力分散（无关任务、闲聊） | ❌ 不引发 | 模型能聚焦当前请求 |
| 误导性先例（之前给过错答案） | ❌ 不引发 | 模型能独立判断 |
| **内容信任（历史细节被当作事实）** | ✅ **引发** | 闲谈细节被升级为事实依据 |
| **润色越界（优化材料时自由发挥）** | ✅ **引发** | 在来源之外添加未证实内容 |

### 3. 对 prompt-promote 设计的新增启示
skill 的核心机制需要补充两条（之前的设计没覆盖）：

1. **事实来源标注**：区分"用户当前请求里明确说的"（绑定）与"历史闲聊/背景信息"（仅供参考、不可作为事实依据）。C11 的"奶奶"就是历史闲聊被误升级为事实。
2. **防润色越界**：改写/优化用户材料时，只允许基于**来源材料**，来源里没有的信息（技术栈、荣誉、数据）不得添加——缺数据用占位符或向用户索要，不得编造。C09 正是栽在这里。

## 结论

- 上下文污染假设**部分证实**：不是所有污染都有害，但"内容信任"型污染能精准触发用户真实遇到过的两类失败（编造、虚构理由）。
- 干净基线 4.85 → 污染基线 4.65 的差距看似不大，但**失败集中在"忠实执行"这一核心卖点上**，而不仅仅是分数差异。
- prompt-promote 的战场明确了：**在脏会话里守住"事实边界"**，而不是把提示词写漂亮。
