# 骨架详解（templates）

本目录记录 8 字段骨架在各类任务下的填充差异。SKILL.md 内是精简版，这里展开讲"每个字段填什么、注意什么"。

## 通用骨架（other）

```
【角色】ROLE
【任务】TASK
【上下文】CONTEXT
【输入】INPUT
【约束】CONSTRAINTS
【输出格式】OUTPUT FORMAT
【示例】EXAMPLE
【评判标准】CRITERIA
```

- 字段全部保留，按字面填充
- 任务必须动词开头、一句话说清

## 写作类（writing）

| 字段 | 侧重 | 注意 |
|---|---|---|
| 角色 | 文体对应的写作者身份 | 如"资深科幻小说作家" |
| 任务 | 写什么、给谁 | 明确文体（邮件/文案/小说/简历） |
| 上下文 | 用户背景、创作现状 | 避免过度发挥 |
| 输入 | 用户提供的素材 | **只允许基于素材改写，素材外不得添加** |
| 约束 | **语气、字数、受众、禁止虚构** | 语气冲突要显式列出（如"既尊重又随意"） |
| 输出格式 | 文体结构、长度 | 约数也要写（"约200字"） |
| 示例 | 质量基准 | 有就放 |
| 评判标准 | 覆盖用户要求 + 不超出素材 | 防润色越界 |

## 代码类（coding）

| 字段 | 侧重 | 注意 |
|---|---|---|
| 角色 | 工程师视角 | 简洁 |
| 任务 | 明确功能/修复目标 | "修 bug"必须定位到具体代码 |
| 上下文 | 运行环境、技术栈 | |
| 输入 | 代码/报错/数据 | 依赖前文代码时**必须定位来源**，定位不到反问 |
| 约束 | **最小修改、不重构、遵守技术约束** | 如"不要用第三方库"逐条列出 |
| 输出格式 | 只给改动部分或完整文件 | 按用户习惯 |
| 示例 | 有就放 | |
| 评判标准 | 修复正确、无副作用、未动无关部分 | 对齐用户"只修复bug" |

## 分析类（analysis）

| 字段 | 侧重 | 注意 |
|---|---|---|
| 角色 | 分析师 | 简洁 |
| 任务 | 分析目标 | |
| 上下文 | 业务背景 | 数据口径 |
| 输入 | 数据/材料 | **数据必须是真实来源，不得编造数据** |
| 约束 | 结论要有数据支撑 | |
| 输出格式 | 结构化：总览/发现/建议 | 对齐"无格式要求"时的默认结构 |
| 示例 | 有就放 | |
| 评判标准 | 覆盖所有维度、结论可追溯 | |

## 翻译类（translation）

| 字段 | 侧重 | 注意 |
|---|---|---|
| 角色 | 专业译者 | 简洁 |
| 任务 | 翻译目标语言 | |
| 上下文 | 文体/受众 | 商务 vs 口语差异大 |
| 输入 | 原文（原样保留） | |
| 约束 | **忠实原文、不增删、保留格式** | 专有名词处理规则 |
| 输出格式 | 译文（+对照可选） | |
| 示例 | 有就放 | |
| 评判标准 | 准确、通顺、无增删 | |
